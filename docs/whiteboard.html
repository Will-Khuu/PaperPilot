RAG Whiteboard

Mapping PaperPilot, a research paper assistant, before any of it is written. The aim is to understand each stage well enough to explain it, and to know how to tell when it is working.

Two pipelines. One shared database.

The whole system on one board

Ingest runs when a paper is uploaded. Ask runs on every question. They only meet in the vector database, which is why the same embedding model has to sit on both sides.

Ingest

runs once per paper
  1. 1

    Upload

    FastAPI file upload

    InA PDF file

    OutThe file on disk, with a paper id

    give every paper an id now. Each chunk carries it later, and compare mode filters on it.

  2. 2

    Parse

    PyMuPDF

    InThe PDF

    OutText blocks in reading order, each with its page number

    PDF text can come out in odd order, with headers, footers and split words mixed in. Print the raw output for one paper before trusting it.

  3. 3

    Chunk

    Plain Python

    InPage text

    OutPieces of roughly 500 to 800 tokens, split at section headings, tagged with page and section

    a chunk is the unit that gets retrieved and cited. Its size sets how precise a citation can be.

  4. 4

    Embed

    Embedding model

    InChunk text

    OutOne vector of floats per chunk (384 numbers for Chroma's default local model)

    text with similar meaning lands close together in vector space. That is the whole trick.

chunks, vectors and metadata get written here

Chroma, the vector database

One collection, one row per chunk. Each row holds text, embedding and metadata (paper id, title, page, section).

the closest chunks get read back from here

Ask

runs on every question
  1. 1

    Question

    Streamlit chat box

    In"What architecture does this paper use?"

    OutThe text, plus which papers are selected

    keep the selected paper ids. They become a filter on the search.

  2. 2

    Embed question

    Same model as ingest

    InThe question text

    OutOne vector

    a different model puts vectors in a different space, and search returns noise.

  3. 3

    Retrieve

    Chroma query

    InThe question vector

    OutTop 5 chunks by distance, with metadata

    build and test this with no LLM attached. If the right chunk is not in the top 5, nothing after it can fix that.

  4. 4

    Build prompt

    String template

    InChunks and question

    OutInstructions, numbered excerpts [1] to [5], then the question

    tell the model to answer only from the excerpts, and to say so when they do not contain the answer.

  5. 5

    Answer

    LLM (Claude or OpenAI)

    InThe prompt

    OutAnswer text with [1], [2] markers

    citations work because you numbered the excerpts. Map each marker back to that chunk's metadata.

One chunk, from the inside

Everything in the system is built around this record. Values are illustrative.

  "id": "attn-p3-c2",
  "text": "The encoder is a stack of identical
           layers, each with a self-attention
           sub-layer and a feed-forward ...",
  "metadata": {
    "paper_id": "attn",
    "title": "Attention Is All You Need",
    "page": 3,
    "section": "3.1 Encoder and Decoder Stacks"
  },
  "embedding": [0.021, -0.113, 0.087, ...]
}

text

What the LLM reads. It goes into the prompt as one numbered excerpt.

metadata

What the citation shows. If you do not store it at ingest, you cannot rebuild it later.

embedding

What search compares. The user never sees it.

Decisions, in the order you will face them

Each note has a starting value and a way to test it. Change one thing at a time and rerun the same questions.

Chunking

Start withSplit at section headings, cap at about 600 tokens, overlap 80 tokens.

WhyA section holds one idea. Overlap protects sentences cut at a boundary.

TestRead 10 chunks by eye. Does each one make sense on its own?

Embedding model

Start withChroma's default local model.

WhyNo API key, fast to iterate. The answer LLM and the embedding model are separate choices.

TestLater, try a hosted model and compare hit rate on your question set.

Distance metric

Start withCosine similarity.

WhyChroma defaults to L2 unless you set the metric when you create the collection.

TestQuery with a sentence copied straight from a chunk. It should come back first.

How many chunks

Start withTop 5.

WhyToo few misses the answer. Too many buries it and costs more per question.

TestRaise to 10 and check whether hit rate actually improves.

Prompt rules

Start withAnswer only from the numbered excerpts, cite as [n], and say when the excerpts do not cover it.

WhyWithout the last rule the model fills gaps from memory.

TestAsk something the paper never mentions. Does it decline or invent?

Compare mode

Start withSearch each paper separately using the paper id filter, take the top 3 from each, then ask the LLM to contrast them.

WhyOne global top 5 lets the paper with more matching text crowd out the other.

TestCompare two papers and check both appear in the sources.

Where it breaks

Most RAG bugs look like model problems and are really retrieval or parsing problems. Check the stage before the LLM first.

SymptomLikely causeTry
Answer sounds right but is wrongThe right chunk was never retrievedPrint the top 5 for that question. Adjust chunk size or k.
Answer misses a number from a tableThe parser flattened or dropped the tableInspect the parsed text for that page. Extract tables separately later.
Citation points to the wrong pageA chunk spans two pages and only one page was recordedStore the start page for each chunk, and the end page if it differs.
One paper dominates a comparisonA single global search over all papersQuery per paper with the paper id filter.
Model answers when the paper is silentThe prompt allows outside knowledgeTighten the rule, then test with unanswerable questions.
Short vague questions return junkThe question vector carries too little meaningLater: have the LLM rewrite the question before searching.

Build order

One step per sitting is plenty. Each step ends with a question to answer out loud before you move on, and a one-line entry in a decisions file saying what you chose and why. Retrieval comes before generation, so by step 3 you can see whether search works with no LLM involved.
